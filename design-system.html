Enterprise Design System

Building a shared design language across multiple product teams, so consistency stops depending on everyone remembering the rules.

My Role

Turning scattered patterns into a shared language.

I was part of the design system team, focused on designing and documenting reusable UI components and patterns, and helping other product teams actually adopt them in their day-to-day work.

  • Component Design
  • Design Tokens & Foundations
  • Documentation
  • Adoption & Enablement
  • UX Writing
  • Cross-functional Collaboration

Overview

Every team was solving the same problems differently.

Across a large organization, multiple product teams designed their own buttons, forms and navigation patterns from scratch. The same problem was solved differently every time, and small visual and interaction inconsistencies accumulated until the products stopped feeling like part of the same family.

This project aimed to give every team a shared design language — reusable components, tokens and content guidelines — so teams could move faster without reinventing the basics each time.

Documentation Pipeline

From Figma component to living code.

I helped co-create the pipeline connecting design and engineering: every component was built once in Figma, then an AI workflow read the file directly to extract the real design tokens and generate structured documentation in Docusaurus, before the component shipped as a live, testable story in Storybook — so design and code always referenced the same source.

A conclusion along the way

Consistency doesn't come from asking teams to be more careful.

Rules alone don't scale across dozens of teams shipping in parallel. What scales is making the reusable option the easiest one — a documented, Storybook-ready component is faster to use than a custom one, so consistency becomes the path of least resistance instead of an extra step someone has to remember.

Outcome

Still growing, already paying off.

The design system is still being built and documented, with new components and patterns added as teams need them.

Even at this stage, teams report cleaner handoffs and faster deliveries, since screens increasingly start from shared, documented components instead of custom one-off work.
