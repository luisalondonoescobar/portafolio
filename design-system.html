Enterprise Design System

Building a shared design language across multiple product teams, so consistency stops depending on everyone remembering the rules.

My Role

Turning scattered patterns into a shared language.

I am part of the design system team. Since the components themselves came directly from PrimeNG's Figma library, my role was to curate which of those components teams actually used, adapting the ones that didn't quite fit as delivered, and design the AI-assisted workflow that turns those Figma components into structured Docusaurus documentation — then help other product teams actually adopt the result in their day-to-day work.

Overview

Every team was solving the same problems differently.

Every product team already shared the same technical foundation — Angular and PrimeNG — but without real components in Figma or documented usage guidelines, teams passed styles around informally between projects. The same problem was solved differently every time, and small visual and interaction inconsistencies accumulated until the products stopped feeling like part of the same family.

This project aimed to give every team a shared design language — reusable components, tokens and content guidelines — so teams could move faster without reinventing the basics each time.

Documentation Pipeline

From Figma component to living code.

I helped co-create the pipeline connecting design and engineering: components came from PrimeNG's Figma library, curated down to what teams actually used, then an AI workflow read the file directly to extract the real design tokens and generate structured documentation in Docusaurus, before shipping as a live, testable story in Storybook — so design and code always referenced the same source.

  • Tone: imperative, direct, action verb.
  • Preferred verbs: Save, Confirm, Continue, Submit, Cancel.

A conclusion along the way

Consistency doesn't come from asking teams to be more careful.

Rules alone don't scale across dozens of teams shipping in parallel. What scales is making the reusable option the easiest one — a documented, Storybook-ready component is faster to use than a custom one, so consistency becomes the path of least resistance instead of an extra step someone has to remember.

Design Tokens

An example: the tokens behind one button.

Every value on the Button component traces back to a named design token, extracted directly from Figma during the AI-assisted documentation pass. The button alone maps to dozens of tokens across every severity, size and state — these six are just a sample:

button.primary.background

Primary button background.

button.secondary.background

Secondary button background.

16px

button.padding.x

Horizontal padding, default size.

8px

button.gap

Space between icon and label.

12px

button.border.radius

Default border radius (md / lg).

3px

button.focus.ring.width

Focus ring thickness.

Six of dozens — the same component defines separate tokens for every severity, size and state, and every other component in the library follows the same pattern.

Outcome

Still growing, already paying off.

The design system is still being built and documented, with new components and patterns added as teams need them.

Even at this stage, teams report cleaner handoffs and faster deliveries, since screens increasingly start from shared, documented components instead of custom one-off work.
